A **React component** is a function that returns some HTML. That's the whole idea. You write a function called `RollCard`, it returns `<div>...</div>`, and now you can use `<RollCard />` anywhere in the app as if it were a built-in tag.

## Props: arguments for components

Components take **props** the way functions take arguments. You pass them as attributes:

## State: data that changes

When something in the UI needs to remember a value over time, it goes in **state**. State is created with the `useState` hook:

## Picking apart a real component

`<RollCard>` is the most-used component in the app — it renders one roll in the feed and history. Here's its essence (simplified):

<AnnotatedCode

  roll: Roll;
  header?: React.ReactNode;
  footer?: React.ReactNode;

  return (
    <article className="rounded-lg border border-surface-2 bg-surface p-4">

      <DrinkBadge size="lg" drink={roll.drink} />
      {roll.is_doubles && <DoublesBadge />}
      {footer}
    </article>
  );
}`}

## What you can do with this knowledge

Whenever you spot a piece of UI that's repeated, that's a candidate for a component. And per CLAUDE.md: *before* you make a new one, search `src/components/` for something close. Adding a `variant` prop to an existing component is almost always better than creating a near-duplicate.
