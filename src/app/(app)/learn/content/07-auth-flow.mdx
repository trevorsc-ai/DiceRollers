Authentication is the single trickiest part of any web app, because it touches the browser, cookies, the server, middleware, and the database all at once. Let's walk one login from tap to redirect.

## Step 1: the login page itself

This is just a normal page with a button. Tapping the button calls `supabase.auth.signInWithOAuth({ provider: "google" })`, which constructs the Google OAuth URL and navigates the browser there. Once Google authenticates the user, it redirects back to a callback URL on our app.

## Step 2: the callback route

The callback is a server-only route (no UI, just code) that exchanges a one-time code from Google for a session. The session gets stored as cookies, then the route redirects to wherever the user was going.

## Step 3: middleware keeps the session fresh

Every request to the app passes through `src/middleware.ts` *before* hitting any page. The middleware's job: read the cookies, validate the session with Supabase, and (importantly) refresh it if it's near expiry, writing new cookies back on the response.

Without this, sessions would silently die after their token expired and users would get random "you're logged out" surprises.

<AnnotatedCode
  filename="src/middleware.ts (sketch)"
  language="ts"
  code={`import { createServerClient } from "@supabase/ssr";

export async function middleware(request: NextRequest) {
  const response = NextResponse.next({ request });

  const supabase = createServerClient(URL, ANON_KEY, {
    cookies: {
      getAll: () => request.cookies.getAll(),
      setAll: (toSet) =>
        toSet.forEach(({ name, value, options }) =>
          response.cookies.set(name, value, options)
        ),
    },
  });

  await supabase.auth.getUser(); // refreshes if needed
  return response;
}`}

## Step 4: pages check who you are

By the time a page renders, cookies are valid. The shared `(app)/layout.tsx` calls `supabase.auth.getUser()` once and either redirects to `/login` or renders the page. Inside any page under `(app)`, you can assume the user is logged in — that gate already ran.

## What you can do with this knowledge

When auth misbehaves — random logouts, "session not found", redirect loops — the cause is almost always in the cookie plumbing. Walk this diagram: did the callback set cookies? Is middleware refreshing them? Is the page reading them from the right client? Eliminate steps one by one and the bug surfaces fast.
