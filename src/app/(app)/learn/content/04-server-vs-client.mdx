Every component in a Next.js App Router app is either a **server component** or a **client component**. The difference is *where the code runs*, and once you internalize it, two-thirds of the surprises in this codebase disappear.

## The default is server

Open any `page.tsx`. Unless the very first line says `"use client"`, that file runs **only on the server**. It never ships to the browser. The user's phone never sees that JavaScript.

That's actually amazing: you can directly `await` a database query in the same function that returns JSX:

## When you need to be on the client

Anything that needs *interactivity* — useState, onClick, useEffect, browser APIs — has to run in the browser. That's a client component. You opt in by putting `"use client"` at the top:

<AnnotatedCode

import { QueryClientProvider } from "@tanstack/react-query";

export default function Providers({ children }: { children: React.ReactNode }) {

## The Roll page uses both

Here's the actual split in DiceRollers:

- `src/app/(app)/roll/page.tsx` → server component. Checks auth, runs once per request.
- `src/components/roll/*` → client components. Handle the die-picking interaction, the confetti, the celebration modal.

The server side fetches the user, the client side handles every tap that follows.

## What you can do with this knowledge

When designing a new page, ask: *what's the minimum that needs to be interactive?* Put everything else on the server. A page with one tiny "use client" island for a button is faster, smaller, and easier to reason about than a fully client-rendered page.
