Deploying isn't "push to GitHub and pray." DiceRollers has a 5-phase pipeline scripted under `scripts/deploy/`, designed so that **migrations land safely before code that depends on them** and **production is always provable**.

## The production stack

- **GitHub** — the source of truth. Every change goes through a PR to `main`.
- **Vercel** — hosts the Next.js app, builds it on every push, auto-deploys `main` to `diceroll.today`.
- **Supabase (linked project)** — the production Postgres + Auth + Storage. Migrations live in `supabase/migrations/`.

## Why migrations ship BEFORE code

This is the rule that prevents most deploy disasters. Imagine you merge code that does `SELECT new_column FROM rolls`, but the migration adding `new_column` hasn't run yet. Production breaks the moment Vercel switches traffic over.

So the order is:

1. Apply migrations to production DB.
2. Verify everything still works (the migration was additive and safe).
3. *Then* merge the code that uses the new column.

If the migration fails, you abort *before* merging anything. Code never references columns that don't exist.

## Multi-session migration drift

There's a wrinkle worth knowing: migrations sometimes get applied from different sessions (Studio UI, a separate Claude session, etc.). When that happens, the local `supabase/migrations/` files can lag behind what's actually in production.

The preflight script catches this by reading the remote `schema_migrations` table and comparing it to your local files. If something's missing locally, it tells you to pull or regenerate before you do anything destructive.

## What you can do with this knowledge

When planning a feature, separate **schema changes** from **code changes** in your head before you start. Ask: *what migration goes first?* That single question prevents most of the dangerous deploy patterns. If the answer is "none — code-only," even better, you can ship a tiny PR fast.

And: **never run a migration in production without preflight first**, even if you're "sure" nothing has drifted. The whole pipeline exists because being sure has burned this app before.
