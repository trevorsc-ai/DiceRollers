**Supabase is three things wrapped together: a Postgres database, an auth system, and a file storage layer.** All three are accessed through one JavaScript client. That's why it shows up everywhere in this codebase.

## What's actually in the database

A Postgres database is a set of **tables**. Each table has columns (like a spreadsheet header row) and rows (like spreadsheet rows). DiceRollers has tables like:

| Table | Roughly what it stores |
|---|---|
| `profiles` | One row per user — name, avatar, is_admin, etc. |
| `rolls` | One row per dice roll — who, when, what they drank, doubles, daily double. |
| `likes` | One row per like — which user liked which roll. |
| `achievements` | The catalog of every possible achievement. |
| `user_achievements` | Who earned what, when. |
| `punch_card` | Repeatable achievement progress. |
| `twinsies_pairs` | Twinsies relationships between users. |

Tables relate to each other via **foreign keys**. A row in `rolls` has a `user_id` column that points at a `profiles.id` — that's how the database knows which user made which roll.

## What Row-Level Security (RLS) is doing

Postgres has a feature called RLS. You write a policy on a table like *"users can only SELECT rolls if user_id = auth.uid()"*. Then *even if* the front-end forgets to filter, the database still won't return rows the user shouldn't see.

This is why the browser and server clients use the **anon key** — that key is intentionally weak. By itself it can't do anything. RLS rules are what actually grant access, based on who the JWT says you are. The service role key skips all those checks, which is exactly why it must never leave the server.

## The auth side

Supabase Auth handles email logins, OAuth (Google/Apple/etc.), magic links, and password resets. Every logged-in user has a JWT — a signed token stored in their cookies. The server client picks up that JWT from cookies automatically. The browser client picks it up from session storage. From your code, you just call `supabase.auth.getUser()` and you get back the current user.

## Storage (we use this less)

The third leg is file storage — uploads to a CDN-backed bucket. DiceRollers uses it for avatars and the daily-double logos. Same client, but with `supabase.storage.from(bucket).upload(...)`.

## What you can do with this knowledge

Whenever you're about to query the database, ask: *am I on the server or the client?* That determines the import. And: *am I doing user-scoped work or admin work?* That determines whether you can use the normal client or need the service role.
