The feed is the most pagination-heavy page in DiceRollers — every roll ever made, oldest scroll into view as you go down. The standard approach (page numbers, "load more" button) would be ugly here. Instead we use **infinite scroll + keyset pagination**, and CLAUDE.md is very specific about how.

## What "keyset" means

Naive pagination uses OFFSET: "skip 20 rows, give me the next 20." Postgres has to count past those 20 every time, and worse, if a row is inserted while you're scrolling, you'll see duplicates ("oh, that's already in my list?") or skip rows.

Keyset pagination uses the **last row's sort key** as the anchor: "give me 20 rows where `created_at < this_value`." No counting, no race conditions, stable as new rolls come in.

## How TanStack Query handles it

`useInfiniteQuery` is the cousin of `useQuery` for this exact pattern. You give it a `queryFn` that knows how to fetch one page, and a `getNextPageParam` that extracts the cursor from each page. Then `fetchNextPage()` does the work.

<AnnotatedCode
  language="tsx"
  code={`const {
  data,
  fetchNextPage,
  hasNextPage,
  isFetchingNextPage,
} = useInfiniteQuery({
  queryKey: rollsFeedQueryKey(),
  queryFn: ({ pageParam }) => fetchRollsPage(supabase, { cursor: pageParam }),
  getNextPageParam: (lastPage) => lastPage.nextCursor ?? undefined,
  initialPageParam: null,
});

const rolls = data?.pages.flatMap((p) => p.rolls) ?? [];`}

    },
    {
      lines: 9,
      title: "How TanStack Query knows when to stop",
      body: "When the fetch fn returns nextCursor: null (because the page had fewer than 20 rows, meaning we hit the end), getNextPageParam returns undefined, and hasNextPage flips to false. The UI hides the 'loading more' indicator.",
    },

## Auto-loading on scroll

The user shouldn't have to tap "load more." The custom hook `useScrollSentinel` watches a div near the bottom of the list and fires a callback when it enters the viewport.

<AnnotatedCode
  language="tsx"
  code={`const sentinelRef = useScrollSentinel(() => {
  if (hasNextPage && !isFetchingNextPage) fetchNextPage();
});

return (
  <div>
    {rolls.map((roll) => <RollCard key={roll.id} roll={roll} />)}
    <div ref={sentinelRef} />
  </div>
);`}
  annotations={[
    {
      lines: [1, 3],
      title: "Guard against double-fires",
      body: "IntersectionObserver can fire repeatedly while the sentinel sits at the threshold. Without hasNextPage && !isFetchingNextPage, you'd spam fetchNextPage and trigger a stack of duplicate requests.",
    },
    {
      lines: 8,
      title: "The invisible div at the bottom",
      body: "useScrollSentinel returns a ref. Attach it to an empty div placed AFTER the list. When that div scrolls into view, the callback fires. It's a clean pattern: no scroll listeners, no math, no positioning logic — IntersectionObserver does all the heavy lifting.",
    },
  ]}
/>

## What you can do with this knowledge

Any time you build a long list — admin user list, history, transactions — reach for `useInfiniteQuery` + `useScrollSentinel`. CLAUDE.md outright bans re-implementing this pattern from scratch, because the existing version handles all the edge cases (deduping, end-of-list detection, isFetching guards) you'd otherwise have to rediscover.
